
- The server never SSHes, never spawns agent processes, never holds a Docker socket. Runners dial out, keep a lease by heartbeat, own their child processes, journal events to disk and resync after any disconnect. A server restart drops sockets only; a runner restart re-attaches to its detached harness processes.
- Secrets: Clerk keys, the credentials master key and the run-token signing key live in the server env. The runner key lives on the machine (`~/.config/mwc/runner.json`, 0600). Claude logins on the Mac/devbox stay in that agent's `CLAUDE_CONFIG_DIR` on the machine (never in the server). Setup-tokens, API keys, gateway headers and sign-ins for container runners are encrypted in `credentials` and delivered per run over the WSS into the process env (never to disk). Run tokens are short-lived JWTs scoped to one run.
- Messages from another agent or from the CEO chat are chat input only; they can never resolve a permission or an approval (Claude Code's own cross-session rule).

## 6. Data model v0 (Postgres; uuid v7 ids; `created_at`/`updated_at`)

Conventions: every tenant table has `company_id` and `UNIQUE(company_id, id)`; child FKs are composite `(company_id, parent_id)`, so cross-tenant references are impossible at the DB level. Enums are CHECK constraints mirrored by zod enums in `@mwc/shared`.

**Global (S1):** `users` (primary_email, display_name, status) · `user_identities` (provider, issuer, subject; UNIQUE(issuer, subject): identity is issuer+subject, never email) · `identity_events` (webhook/SCIM inbox; UNIQUE(provider, external_event_id); status pending|processed|failed) · `identity_outbox` (local-first provider ops create_org|invite|revoke_invite|update_role|remove_member|delete_org; idempotency_key; retries) · `companies` (slug, name, status provisioning|active|suspended|deleted, identity_provider, identity_org_id UNIQUE, settings).

**Tenant (S1):** `principals` (kind person|agent; the single id space every actor/assignee FK points to) · `memberships` (principal_id, user_id, role owner|admin|member|viewer, status invited|active|suspended|removed, external_membership_id; UNIQUE(company_id, user_id); ≥ 1 active owner) · `invitations` (email_normalized, role, status, external_invitation_id, expires_at; one pending per email) · `api_keys` (principal_id, kind personal|runner|scim, machine_id, prefix, sha256 hash, scopes, expires_at, revoked_at) · `audit_log` (one row per changed field: entity, action, field, old, new, actor, request_id).

**Tenant (S2):** `agents` (principal_id, name, slug, role_title, status active|paused|archived, harness claude_code|codex, model, effort, instructions, instructions_rev, max_concurrent_runs default 1, settings) · `org_positions` (principal_id, reports_to_principal_id, title; invariants: no cycles, agents never root, an agent's chain reaches a person, agents never manage people).

**Tenant (S3–S6):** `machines` (name, kind laptop|vm|container, os, arch, unix_user, claude_version, runner_version, slots, status online|offline|draining, last_seen_at) · `enrollment_tokens` (sha256, expires_at, used_at) · `runner_sessions` (machine_id, connected_at, disconnected_at, protocol, remote_ip) · `runner_releases` (version, url, sha256, sig, min_runner_version) · `agent_placements` (agent_id, machine_id, home, config_dir, worktree_root, permission_policy ask|bypass, unix_user, is_default) · `tasks` (per-company number, title, body, status backlog|todo|in_progress|in_review|blocked|done|cancelled, assignee_principal_id, created_by_principal_id, parent_task_id) · `messages` (task_id, author_principal_id, kind user|agent|system, body, attachments) · `task_sessions` (task_id, agent_id, machine_id, folder, harness, session_id, state active|superseded) · `runs` (task_id, agent_id, machine_id, placement_id, session_id, state queued|offered|starting|running|lost|completed|failed|stopped, waiting_on null|permission|question, lease_expires_at, started_at, finished_at, exit_code, error, cost_usd, usage, last_seq; partial UNIQUE one live run per task) · `run_events` (id bigserial, run_id, seq, kind, data, at; UNIQUE(run_id, seq)) · `run_inputs` (run_id nullable, task_id, kind message|answer, payload, delivered_at, acked_at) · `attention_items` (kind question|permission|blocked|review|failed|done, state open|answered|dismissed|expired, task_id, run_id, to_principal_id = nearest person up, wait_mode live|next_turn, prompt/options jsonb, answer jsonb, answered_by, expires_at, tool_use_id) · `credentials` (kind, scope_principal_id, provider, ciphertext AES-256-GCM, AAD `company|owner|provider`, key_version, meta) · `credential_deliveries` (credential_id, run_id, at).

Tenant-scoping rule in code: `tenant(db, companyId): TenantDb` is the only way route code reaches tenant tables (`scoped(table)` injects `eq(table.companyId, companyId)`); the raw handle `@mwc/db/system` is import-restricted (Biome `noRestrictedImports`) to migrations, the webhook inbox, the runner hub and jobs. Routes get `c.var.tenant` only after `requireMembership(role)`. No RLS in v0 (one DB role; composite FKs + lint rule + the generated cross-tenant fuzz test give the guarantee); adding `SET LOCAL app.company_id` + policies later is mechanical.

## 7. Identity flow (Clerk now, other IdPs later)

- **Sign-in:** web uses `@clerk/react`; API calls carry `Authorization: Bearer <session token>`. Server `authn()` verifies with `@clerk/backend` `verifyToken` (JWKS or `CLERK_JWT_KEY`, issuer, `authorizedParties=[WEB_ORIGIN]`, 5 s skew). Claims used: `iss`+`sub` (identity key), `sid`, `azp`, `exp/nbf`, `sts` (reject `pending` except on `/api/me`); Clerk's `o.id`/`o.rol` are hints only. Authorization never trusts the org claim: routes are `/api/companies/:companyId/...` and `requireMembership()` reads our `memberships`. First sight of an `(iss, sub)` runs reconcile-on-sign-in (upsert user; project memberships of companies whose `identity_org_id` matches).
- **Create company:** one transaction inserts company(provisioning) + person principal + owner membership + root position + outbox `create_org`; the outbox worker calls Clerk `createOrganization({privateMetadata:{mwc_company_id}})`; retries find the org by metadata (v1a pattern); then the company turns active. Policy `MWC_COMPANY_CREATION=any|allowlist|none`.
- **Invite:** insert invitation(pending) + outbox `invite` → Clerk `createOrganizationInvitation({role map, privateMetadata:{mwc_invitation_id, mwc_company_id}, redirectUrl: /accept-invitation, expiresInDays: 14})`. Honor Clerk's 250/h limit and `Retry-After`.
- **Accept:** three paths funnel into one idempotent projector: webhook `organizationMembership.created` / `organizationInvitation.accepted`; reconcile-on-sign-in of the invitee; periodic reconcile (10 min per company) + manual "Sync now". Link by `mwc_invitation_id` metadata or the external invitation id, never by email. Role comes from our invitation row. Inbound Clerk role changes map `org:admin`→admin (never auto-owner); our DB wins on conflict.
- **Role change / remove / delete:** local first (access ends immediately), then the outbox op to Clerk; last-owner guard; removal re-parents direct reports and revokes the person's API keys; company delete is soft (`status=deleted`, name confirmation); hard purge is a later job.
- **Multi-company:** `GET /api/me` → user + memberships; the active company is the URL `/c/:slug`; the web also calls Clerk `setActive` so Clerk components stay coherent; Clerk "Personal accounts" stays enabled so `sts=pending` never blocks.
- **Service auth:** `api_keys` secrets `mwc_<pk|rk|sc>_<base62×32>` shown once, SHA-256 stored; personal keys expire ≤ 365 days (default 90); runner keys bound to a machine; **run tokens** are server-signed EdDSA JWTs `{typ:'run', cid, rid, aid, exp}` (1 h sliding, revoked by run state). `authn()` yields `Actor{kind user|agent|runner|system, via clerk|api_key|run_token}`.
- **Webhooks in dev:** reconcile is the default and webhooks are optional. For the real two-user test, run `ngrok http 9950` once and point the Clerk dev endpoint at `/api/webhooks/clerk` (raw body → `verifyWebhook` → `identity_events` deduped on svix id → process; `data.updated_at` guards ordering; never recreate a deleted object).
- **`IdentityProvider`** (`packages/identity-core`): `verifyAccessToken`, `getUser`, `listUserOrganizations`, `createOrganization`, `findOrganizationByMetadata`, `deleteOrganization`, `listOrganizationMembers`, `updateMemberRole`, `removeMember`, `createInvitation`, `revokeInvitation`, `listInvitations`, `parseWebhook` → normalized events (`user.upserted|deleted`, `org.upserted|deleted`, `membership.upserted|deleted`, `invitation.accepted|revoked`), plus `capabilities{organizations, invitations, webhooks, scim}`. A future `OidcScimProvider` verifies any issuer's JWKS with `jose`, keeps companies local, and exposes SCIM 2.0 routes (`/scim/v2/Users|Groups|ServiceProviderConfig|Schemas|ResourceTypes`, bearer = `api_keys.kind='scim'` per company) whose writes become the same normalized events (attribute map: `userName`→email, `externalId`→subject, `active`→status, Groups→roles). Clerk's own Directory Sync (inbound SCIM from Okta/Entra, GA 2026-04-16, self-serve since 2026-09-30; billing may change 2027-01-01) covers most enterprise IdPs with no code from us.

## 8. Runner protocol v1 (`@mwc/shared/runner-protocol.ts`, doc `docs/runner-protocol.md`)

- **Transport:** one outbound WebSocket per runner, `GET /api/runner/ws`, subprotocol `mwc-runner.v1`, JSON frames validated by zod on both sides (max 256 KB; event batches ≤ 100 events / 64 KB; ping/pong every 20 s). WS over long-poll because the server must push answers, mid-turn input and stops with low latency; over gRPC because bidi streams and a proto toolchain buy nothing in a zod monorepo and WS passes IAP/NAT/ingress unchanged.
- **Enrollment and auth (Buildkite-style tiers):** `POST /api/machines/enrollment-tokens` (UI/CLI) → `mwc runner install --server URL --token mwc_et_…` → `POST /api/runner/enroll {name, os, arch, hostname, unix_user, claude_version}` → `{machine_id, runner_key mwc_rk_…}` (0600 on the machine; sha256 in `api_keys`). `key.rotate` rotates it with a 10-minute overlap. Each run gets its own run token for MCP/API callbacks.
- **Runner → server:** `runner.hello{protocol:1, version, caps{harnesses, slots}}` · `runner.heartbeat{awake_ms, load1, live_runs[], backlog, now}` every 20 s (= lease renewal) · `runner.resync{runs[{run_id, state running|exited|gone, exit_code, last_seq}]}` on every (re)connect · `job.accept|job.decline{id, run_id, reason}` · `run.events{events[{run_id, seq, at, kind, data}]}` · `attention.create{id, run_id, kind, wait live|next_turn, prompt, options}` · `cmd.ack{cmd_id, ok, error}`.
- **Server → runner:** `server.hello{protocol, min_runner_version, update?{version,url,sha256,sig}}` · `job.offer{id, run_id, agent_id, expires_at}` · `run.start{cmd_id, spec}` (spec: ids, harness, placement{home, config_dir, worktree}, session{mode new|resume, session_id}, model, effort, permission_policy, system_prompt, inputs[], secrets (env only, never journaled), run_token, limits) · `run.input{cmd_id, run_id, input_id, text}` · `attention.resolved{cmd_id, run_id, attention_id, answer, by}` · `run.stop{cmd_id, run_id, mode graceful|kill}` · `run.ack{run_id, acked_seq}` · `key.rotate` · `runner.drain`.
- **Semantics:** events carry `(run_id, seq)` assigned at journal-append time; the server inserts `ON CONFLICT DO NOTHING` and acks the highest contiguous seq; commands carry `cmd_id` and are acked; duplicates after reconnect are normal. Lease `runs.lease_expires_at = now()+90 s`; lapse → run `lost` (never cancelled/failed: the v1 Mac-sleep bug), machine `offline`; on reconnect the resync reconciles `running`→running, `exited`→finalize from the journal, `gone`→`failed(runner_lost_process)` + auto re-run in the same conversation. `job.offer` expires after 30 s unaccepted and is re-offered. Backpressure: ≤ 500 unacked events in flight, then the runner stops advancing its read cursor (disk keeps everything). Unknown message types are ignored; unknown fields pass through.

## 9. Runner daemon (`apps/runner`)

- **Install:** `mwc runner install --server URL --token mwc_et_… [--name]` writes `~/.config/mwc/runner.json`, enrolls, and installs a service: macOS `~/Library/LaunchAgents/com.mwc.runner.plist` (KeepAlive, RunAtLoad, user session so the agent's OAuth works); Linux `systemd --user` unit + `loginctl enable-linger` (devbox); container: PID 1 under `tini`, no self-update. `mwc runner status|start|stop|logs|login --agent <slug>` (runs `claude auth login` under that agent's `CLAUDE_CONFIG_DIR`).
- **State dir** `~/.local/state/mwc-runner/` (`/var/lib/mwc-runner` in containers): `runner.sock` (MCP shim + health), `releases/<v>/` + `current`, `agents/<slug>/claude` (per-agent `CLAUDE_CONFIG_DIR` when the server does not name one), `runs/<run_id>/{spec.json (secrets stripped), token, mcp.json, settings.json, system-prompt.md, in.ndjson, in.fifo, feeder.pid, pid, pgid, exit, out.ndjson, err.log, events.ndjson, cursor.json, commands.ndjson}`.
- **Detached spawn (v1's trick, now local):** `setsid sh -c '{ tail -c +1 -f in.ndjson > in.fifo & echo $! > feeder.pid; }; exec "$@" < in.fifo > out.ndjson 2> err.log; echo $? > exit.tmp && mv exit.tmp exit'` with `MWC_RUN_ID` in env; Node `spawn({detached:true}).unref()`. The feeder, not the runner, holds the fifo open, so a runner restart cannot EOF Claude's stdin. **Re-attach** at boot: for each run without `exit`, check `pgid` alive and `MWC_RUN_ID` in the process env; attached → tail `out.ndjson` from `cursor.out_offset`; gone → report `gone`. Each parsed line becomes normalized events appended to `events.ndjson` (the outbox, fsync per batch) then sent; `run.ack` advances `acked_seq`; `events.ndjson` of finished runs is deleted after ack, `out.ndjson` after 7 days.
- **Health :9953** (`{connected, live_runs, backlog, version}`). **Server down:** runs continue, journal grows, inputs queue server-side in `run_inputs`; reconnect backoff 1→60 s with jitter, never gives up. **Mac sleep:** awake time via monotonic deltas; a heartbeat gap > 2× interval triggers an immediate resync. **Self-update:** `server.hello.update` → download to `releases/<v>/`, verify sha256 + Ed25519 signature (baked-in public key), flip `current`, exit 75 when idle (the service manager restarts it); `runner.drain` stops accepting offers first. **Stop ladder:** SIGINT (ends the turn with a `result`), 20 s, SIGTERM (exit 143), 10 s, SIGKILL the pgid; the `exit` file is the proof; the server marks `stopped` only after the exit event or a `gone` resync.
- Mac note: Kandji bills every process start, so the runner spawns one Claude process and one MCP shim per run, never a process per tool call, and keeps PATH short.

## 10. Harness driver `claude_code` (`packages/harness`)

`HarnessDriver` (harness-agnostic): `buildSpawn(spec, runDir)`, `parseLine(line, state) → RunEvent[]`, `encodeInput(text, input_id)`, `sessionIdFrom(initEvent)`, `interruptSignal`. A `codex` driver later maps `codex exec --json` / `codex app-server` JSON-RPC (thread/start|resume, turn/start|steer|interrupt, approval and `tool/requestUserInput` requests) onto the same events.

Spawn (cwd = the agent's home so its CLAUDE.md, skills and memory load; the task worktree is `--add-dir`, which grants file access without loading that folder's `.claude` config):

```
claude -p --output-format stream-json --input-format stream-json --verbose --replay-user-messages
  (--session-id <uuidv5(task)> | --resume <session_id>)
  --model <model> [--effort <effort>]
  --mcp-config <run>/mcp.json --strict-mcp-config

     (CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_CUSTOM_HEADERS), CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1 on re-attach
```

- Verified against the Claude Code docs on 2026-11-03 (installed CLI 2.1.317): `-p` starts in Manual mode since 2.1.302, so a permission host (`--permission-prompt-tool mcp__…`) is mandatory for `ask` placements; `--settings` overrides machine settings (kills the v1 "box settings override the gateway" bug); SIGINT ends the turn, SIGTERM exits 143; `--replay-user-messages` echoes our user messages back with our uuid, which is the delivery receipt (`input_ack`). The documented PreToolUse `defer` path (`stop_reason: tool_deferred`, resume with `updatedInput`) is kept as a v2 option for native AskUserQuestion.
- Event mapping: `system/init` → `status{session_id, model, tools, mcp_servers, cwd}` · assistant text → `text` (`parent_tool_use_id` → `subagent` scope) · `tool_use` → `tool_use` (`Agent`→`subagent`, `TodoWrite`→`todo`) · `tool_result` → `tool_result` (16 KB cap, `is_error`) · `system/compact_boundary` → `compaction` ("Context compacted") · `system/api_retry` → `status{retry, error}` (auth failures become a `failed` attention item) · `result` → `result{is_error, num_turns, total_cost_usd, usage, permission_denials, session_id}` · stderr tail → `stderr`. The final `result.result` text is posted as the agent's reply.
- Sessions: the server chooses the session UUID (uuidv5 of the task id); `mode:new` with `--session-id` once, `resume` afterwards; `task_sessions` is superseded only when `(machine_id, folder)` changes or resume fails ("No conversation found" → one automatic retry as `new`, announced in the thread). The appended system prompt is stable per task (identity, tool rules, task URL; never a run id or timestamp), because the v1 resume broke on exactly that.
- Metaharness rule: user turns are the human's (or agent's) messages verbatim (first turn = title + body as written); protocol lives only in the system prompt; an answered question arrives as `Answer to "<question>": <label or text>`; the agent never calls an API to reply.
- A run = one process = one or more turns: after a `result` with nothing queued, the runner kills the feeder (EOF) so the process exits; the next message starts a `resume` run.

In-runner MCP server: `mcp.json` = `{"mcpServers":{"mwc":{"command":"<current>/bin/mwc-runner","args":["mcp","--run-dir","<run>"]}}}`, a stdio shim per run (per-run dir fixes the shared-config bug) that forwards JSON-RPC over `runner.sock` with `<run>/token`, retrying up to 120 s while the daemon restarts. ## 11. Human-in-the-loop semantics (inbox)

| Kind                 | Run while waiting                                                                       | Answer path                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `permission`         | stays live (mid-flight tool call, answers take seconds to minutes); auto-deny at 15 min | live tool result                                                                                         |
| `question`           | live for 90 s, then the turn ends with a short line                                     | live tool result, or the answer is posted as the human's thread message and wakes the task (resume turn) |
| `blocked` / `review` | the turn ends                                                                           | the next human message (or approve / request changes) starts a new turn in the same conversation         |
| `failed`             | —                                                                                       | "run again in the same conversation" or close                                                            |
| `done`               | —                                                                                       | informational                                                                                            |

Routing: `to_principal_id = nearestPersonUp(agent)` via `org_positions`, fallback the company owner. Resolve is a compare-and-set `open→answered` (409 otherwise). A thread reply by that person while a question is open closes it (v1 rule). The inbox shows only open items addressed to me; the org chart shows "Waiting for you" over "Working". Delivery to the CEO chat: `mwc inbox list|answer|watch`, MCP tools `inbox_list`/`inbox_answer`; optional Claude Code status-line/hook recipe using `mwc inbox count`.

## 12. Server-side run model (`apps/server/src/modules/{machines,tasks,runs,attention}`)

- **State machine:** `queued → offered → starting → running ⇄ lost → completed | failed | stopped`; `waiting_on ∈ {null, permission, question}` is a sub-state of `running`; a partial unique index enforces one live run per task.
- **Wake:** `POST /api/tasks/:id/messages` by anyone but the assignee agent → a live `running` run gets `run_inputs(message)` + `run.input`; `queued/offered` → nothing (start delivers all undelivered inputs in order); none → insert `queued`.
- **Scheduler** (`LISTEN mwc_queue` + 5 s tick, `FOR UPDATE SKIP LOCKED`): pick a placement on a connected machine with a free slot and agent concurrency → `job.offer`; `starting` on `job.accept`; `running` on the first event. **Reaper** (30 s): expired lease → `lost`; `offered` > 30 s → `queued`; `lost` > 24 h → `failed(runner_lost)` with one-click re-run; permission items > 15 min → `expired` + deny. Nothing lives in memory: after a server restart, schedulers and reapers rebuild from rows and the next `runner.resync`.
- **SSE:** `GET /api/tasks/:id/stream`, `GET /api/inbox/stream` emit `run_event|message|attention|run_status` with `id` = row ids, honor `Last-Event-ID`, fed by `NOTIFY`.
- **Endpoints:** `POST /api/runner/enroll`, `GET /api/runner/ws`; `GET/POST /api/machines`, `POST /api/machines/enrollment-tokens`, `POST /api/machines/:id/drain`; `GET/POST /api/agents/:id/placements`; `GET/POST /api/tasks`, `GET/POST /api/tasks/:id/messages`, `GET /api/tasks/:id/stream`, `GET /api/tasks/:id/runs`, `POST /api/runs/:id/stop`, `GET /api/runs/:id/events?after=`; `GET /api/inbox`, `POST /api/inbox/:id/answer {option_ids?|text?|decision?}`, `POST /api/inbox/:id/dismiss`; `GET/POST /api/credentials` (S6). All under `/api/companies/:companyId/…` where tenant-scoped.
- **UI minimum:** task thread with inline run events and status; inbox with option buttons / text / allow-deny; machines page (online, slots, versions, live runs); org chart; members.
